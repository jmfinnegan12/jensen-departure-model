# Event Neutral page brief

- Look: in the category of the rpsychologist.com visualization pages. Not a copy. Dark by default, with a light/dark switch. No monospace labels. Charts in D3 (version 7).
- Tone: "serious but accessible". Not "codey or techy", not "overly simplistic or overly warm and friendly".
- Words: minimal. Write for an educated adult: proper terms, nothing obvious. A description stays only if it adds a reason the reader needs.
- Precision: say exactly what a thing does (an input is not an assumption). Claim only what is known, mark open questions as open, source every factual claim.
- Jim's words: when he gives his reasoning, record it verbatim, then use it close to verbatim. If there is none, ask.
- Model rationale: general idea first, specifics after. His rationale for default values gets its own section; text beside a control only says what the control is.
- A chart must be readable without an explanation.
- Every event site has a rules page for its market. Every model page has an "Update log" dropdown beside its rationale, assumptions and weak points: one dated, sourced line per change, newest first, what changed and why.
- Structure and choice of visuals are open. They follow the question.
- Apply a correction everywhere it applies, not only where it was pointed out.
- Before showing the page: open it in a browser, compare it with the references and earlier finished pages, and fix what falls short.

Project background lives in the owner's notes, not here: "Event Neutral value proposition" and "Event Neutral vision and mission" in the Personal vault.
