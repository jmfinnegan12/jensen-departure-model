# Event Neutral page brief

- Look: in the category of the rpsychologist.com visualization pages. Not a copy.
- Tone: "serious but accessible". Not "codey or techy", not "overly simplistic or overly warm and friendly".
- Dark by default, with a light/dark switch. No monospace labels.
- Charts: D3 (version 7).
- Words: minimal. No fluff. Write for an educated adult: use the proper term for a thing, and never state the obvious. A description stays only if it adds a reason the reader needs.
- Use Jim's words. Where he has dictated or written his reasoning, find it and use it close to verbatim. If there is none, ask.
- Be precise. Say exactly what a thing does. An input is not an assumption.
- Claim only what is known. Mark open questions as open.
- Source every factual claim.
- In a model rationale, give the general idea first and the specifics after.
- Apply a correction everywhere it applies, not only where it was pointed out.
- When Jim gives his reasoning in a session, record it verbatim before summarizing it.
- Structure and choice of visuals are open. They follow the question.
- Before showing the page: open it in a browser, compare it with the references and earlier finished pages, and fix what falls short.

Project background lives in the owner's notes, not here: "Event Neutral value proposition" and "Event Neutral vision and mission" in the Personal vault.
